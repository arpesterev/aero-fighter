# AERO FIGHTER / DAGOR NATIVE

Нативная визуализация наблюдательного поста на **Dagor Engine**. Никакого Node.js, npm, браузерной сцены или Three.js в рабочем варианте больше нет.

**Идея:** второй монитор показывает непрерывное небо. Спокойно в режиме дежурства. API получает событие `contact`, `engage_light` или `engage_heavy`, в сцене появляются условные воздушные отметки и начинается визуализация огня нескольких наземных зенитных позиций: трассеры, вспышки, воздушные искры. **Только внешнее событие `clear` останавливает активную сцену.** Достижение условной цели, истечение времени, обновление кадра или перезапуск API не являются сигналом отбоя.

## Что реализовано и что ещё нет

- **Реализовано в исходниках:** C++17-модель непрерывной сцены с пятью детализированными процедурными позициями, двумя режимами стрельбы, вспышками у стволов, световыми трассерами, воздушными разрывами, искрами, дымом и ограничением памяти эффектов.
- **Реализовано в исходниках:** нативный рендерер Dagor на геометрии из 3D-треугольников: объёмные корпуса и стволы зениток, радар, база, световые слои, воздушные импульсы и многослойный полупрозрачный дым. Освещение ориентируется на локальное время macOS.
- **Реализовано и локально протестировано:** API на Python 3 без зависимостей. Он слушает исключительно `127.0.0.1`, атомарно записывает состояние на диск; C++ сцена читает его из файла.
- **Не проверено на физическом Mac:** компиляция полного Dagor + Metal, размещение окна на втором мониторе, цветокоррекция и финальный внешний вид. CI компилирует C++-слой эффектов и рендер-адаптер с минимальными заглушками Dagor, но это не GPU-тест.
- **Не реализовано:** фотограмметрические / лицензированные модели War Thunder, физический объёмный дым и реальное освещение частиц, HDR bloom через нативный post-processing, полноценный UI и звук сирены. Дым сейчас представляет собой многослойные 3D billboards, техника смоделирована процедурно.

Это **первый исполняемый нативный прототип по коду**, а не готовая копия War Thunder. Собственно исходники War Thunder, её графические ассеты и физика не входят в открытый Dagor Engine. **Это полноценный по структуре исходный VFX vertical slice, а не подтверждённый macOS-релиз.**

## Запуск на Mac

Понадобятся macOS, Xcode Command Line Tools, Python 3, `git`, `7zz` или `7z` (семейство 7-Zip). Требуется место для исходников движка, инструментария и ассетов; сборка ресурсоёмкая.

```bash
git clone --recurse-submodules https://github.com/arpesterev/aero-fighter.git
cd aero-fighter
bash scripts/build-macos.sh --install
bash scripts/run-macos.sh
```

Первая команда сборки использует [Dagor Engine релиза 2026-08-01](https://github.com/GaijinEntertainment/DagorEngine/releases/tag/dagor_2026_08_01), скачивает официальные инструменты macOS (~213 МБ) и исходные двоичные пакеты `tools-base.7z` (~26 МБ) и `samples-base.7z` (~203 МБ), патчит `skiesSample` и запускает сборку C++, шейдеров и ресурсов. Скачивание выполняется только при запуске с `--install`; скачанное не коммитится. Пакеты поставляются издателем, но независимая криптографическая проверка подписей здесь не выполнена.

Если движок уже установлен и базовые ресурсы есть, достаточно:

```bash
bash scripts/build-macos.sh
bash scripts/run-macos.sh
```

Если скрипт не определил путь к собранному исполняемому файлу, передай его явно:

```bash
AERO_FIGHTER_BIN="/абсолютный/путь/к/SkiesSample" bash scripts/run-macos.sh
```

При запуске открывается **нативное окно Dagor**, которое можно перенести на второй монитор и развернуть. Python API стартует рядом и завершается вместе с приложением. Браузерное окно для рендера больше не требуется.

### API событий

```bash
# Обнаружить цель, без огня
curl -X POST http://127.0.0.1:8011/api/event \
  -H 'Content-Type: application/json' \
  -d '{"type":"contact","targets":2}'

# Лёгкий огонь: 2 из 5 позиций
curl -X POST http://127.0.0.1:8011/api/event \
  -H 'Content-Type: application/json' \
  -d '{"type":"engage_light","targets":3}'

# Интенсивный огонь: 5 позиций, продолжается без таймера
curl -X POST http://127.0.0.1:8011/api/event \
  -H 'Content-Type: application/json' \
  -d '{"type":"engage_heavy","targets":4}'

# Только ЭТО прекращает тревогу и огонь
curl -X POST http://127.0.0.1:8011/api/event \
  -H 'Content-Type: application/json' \
  -d '{"type":"clear"}'
```

Совместимость: старые `alert`, `incoming`, `engage` преобразуются в `contact`, `engage_light`, `engage_heavy`. Поле `targets` (или `count`) принимает целое 1–6. `siren` пока только валидируется; **звука не будет**. Поля `duration` нет: активность может остановить исключительно внешний `clear`.

Проверка статуса: `GET http://127.0.0.1:8011/api/state`. Долговременное состояние хранится в `.runtime/aero.state` в формате `AERO1 <seq> <mode> <targets>`. При перезапуске сервер и нативная сцена читают предыдущую команду. Если файл содержит активный режим, работа продолжается.

## Что за сцена

- `engine/dagor`: официальный Dagor Engine, закреплённый Git-подмодуль.
- `native/include/aero_scene.h`: движконезависимый автомат состояний, расписание очередей, цели, динамика трассеров, искр, вспышек и дыма (C++17).
- `native/dagor/aero_fighter_overlay.h`: геометрические модели базы/зенитных точек, многослойные световые трассеры, 3D billboard-дым и эффекты поверх атмосферного `skiesSample`.
- `scripts/prepare_dagor.py`: проверяемая идемпотентная интеграция с примером, с резервным сохранением исходного файла внутри подмодуля.
- `native/api_server.py`: минимальный HTTP API без npm и сторонних Python-библиотек.
- `scripts/build-macos.sh`, `scripts/run-macos.sh`: сборка и запуск на macOS.
- `tests/`: C++ и Python-тесты для логики, API и патча.

**Ограничения проверки:** CI проверяет C++-модель и API на Linux, но **не собирает Metal-версию Dagor**. [Технические подробности](docs/DAGOR.md).

### Проверка эффектов без Mac

```bash
c++ -std=c++17 -Wall -Wextra -pedantic -Werror -O2 tests/test_scene.cpp -o /tmp/aero-scene && /tmp/aero-scene
c++ -std=c++17 -Wall -Wextra -pedantic -Werror -O2 -Itests/stubs -Inative/include tests/test_render_stub.cpp -o /tmp/aero-render-stub && /tmp/aero-render-stub
```

Второй тест проверяет совместимость вызовов нашего рендера с **заглушками** публичного интерфейса Dagor. Он не подтверждает сборку движка и работу настоящего GPU.
